# Task Graph

Parity work is a dependency graph, not a list. A Ghidra question must be
answered before its review, the review before the port, and the port before
the A0 cells it fixes can pass. The graph holds that order, so the next piece
of work is whatever is unblocked and ranks highest, and it can be handed to
any agent one node at a time.

It is kept with [br](https://github.com/Dicklesworthstone/beads_rust)
(beads_rust) and read with
[bv](https://github.com/Dicklesworthstone/beads_viewer) (beads_viewer).

## Files

| Path | Tracked | What |
|---|---|---|
| `.beads/issues.jsonl` | yes | The graph: one node per line. The source of truth in git. |
| `.beads/config.yaml` | yes | `issue_prefix: or`, `claim_exclusive: true`. |
| `.beads/policy.yaml` | yes | `workflow.required_fields`: a close needs every acceptance box checked. |
| `.beads/metadata.json`, `.beads/.gitignore` | yes | br's own. |
| `.beads/beads.db` and its sidecars, locks, `.br_history/` | no | A local cache, rebuilt from the JSONL. |
| `tasks/*.md` | yes | The graph as pages for collaborators: an index with the epics, the work in progress and the ready work, then one page per kind of node and one for closed nodes. Generated by `scripts/task-index.py`; never edited by hand. |
| `.git/info/task-index-deny` | no | Extra text the generator refuses to publish, one pattern per line. |

The root `.gitignore` ignores `*.jsonl`; `!.beads/issues.jsonl` keeps the
graph tracked. br never runs git: after `br sync --flush-only`, run
`scripts/task-index.py` and stage `.beads/issues.jsonl` and `tasks/` with the
code they describe, in the same commit. `scripts/task-index.py --check` fails
when the pages lag the graph.

## Nodes

A standalone node's ID reads `or-<slug>-<hash>`, such as
`or-q-results-window-yln` (`br create --slug <kind>-<name>`). A plan's beads
are dotted children of the plan's epic: `br create --parent <epic>` (which
ignores `--slug`) gives `or-ep-<plan>-<hash>.1`, `.2`, and `.1.1` for a
subtask, at most two levels, with the `parent-child` edge recorded. Priority
runs P0 (now) to P4 (someday). Five epics group the nodes through `parent-child`
dependencies: tactical parity, the ground assault (TAC-08), Ghidra coverage,
the REBEXE map (every function and undefined code span given a role and a
cluster), and the mod surface (what the original fixes in code that mods
would need as data; closed).

The label says what kind of work a node is:

| Label | Work | Done when |
|---|---|---|
| `question` | One question about the original, answered from the executable. | A note answers it with function and address citations, both sides where the code branches, and the cited decompiles are attached. |
| `map` | A `question` that maps one REBEXE address range: every function and undefined code span in it gets a role, a cluster and a proposed name. | The range's map note accounts for every function and gap, with citations, and is merged. |
| `review` | Rereading a question's decompiles against our own Ghidra project. | Every claim is confirmed or corrected, and the `.c` files and the note are in `ghidra/notes/`. |
| `port` | Changing the port to match. | The code cites the recovered functions and works end to end in the running game, both factions. |
| `diagnose` | Naming the causes of a failing comparison region. | Each difference has its own port or question node. |
| `fixture` | An A1 scenario reproducing an A0 save, so its cells run. | The cells run (pass or fail). |
| `acceptance` | A comparison region across its listed cells. | `tactical-a0-compare.mjs --negative-controls` passes the region in every listed cell, and the negative controls fail their rows. |
| `capture` | A0 references from the original in the capture VM. | Frames and hashes are in the A0 manifest. |
| `verify`, `chore` | A check or a mechanical task. | As its description says. |
| `decision`, `owner` | Needs Tom: a plan to approve, a commit to land. | Tom has decided. |
| `worker-ok` | May be handed to a delegated agent. | |

Only `question` nodes carry `worker-ok`. Reviews, ports and acceptance stay
with the lead session, which runs the native build, the battle runner and
the capture VM.

Every open node carries its "Done when" as a checklist in the
`acceptance_criteria` field (`- [ ]` items). `br lint` reports a task without
one, an epic without `## Success Criteria` and a bug without
`## Steps to Reproduce`; `scripts/gates.sh`'s `beads` gate fails on any such
warning, a dependency cycle or a closed node with an unchecked box.
`.beads/policy.yaml` refuses to close a node while a box is unchecked.

## A bead

A bead is self-contained: an agent can do the work from the bead alone,
without reopening the plan. Its `description` is markdown with these
headings, and its criteria live in `acceptance_criteria`:

| Part | What it holds |
|---|---|
| `## Background` | The original's behaviour, cited (`FUN_`/`DAT_`/GNPRTB, manual page), both sides where the code branches, and why the plan needs it. |
| `## Scope` | The files and crates that change, what changes, and what stays out. |
| `## Design` | The approach and the options rejected, when it is not obvious. |
| `acceptance_criteria` | `- [ ]` items, each checkable on its own: both factions, the evidence named by save, day and values. |
| `## Tests` | The behaviour-sentence unit tests by name with their citations, shown red first in a Mini clone, and `cargo mutants` on the touched functions. |
| `## E2E` | The native dev-command batch (`agent_docs/dev-commands.md`) and/or the `tools/interface-parity` gate that proves it, both sides, silent. |
| `## Evidence` | The trace masks or log lines to capture. Never an `.artifacts/` path. |
| `## Constraints` | "AGENTS.md applies" plus anything particular to this bead. |

A `question` or `map` bead is shorter: `## Question`, `## Where to look`
(functions, addresses, notes), and criteria that name the note, its
citations and the attached decompiles.

## Plans and epics

A plan in `docs/plans/` is the reviewed spec and the record of its evidence.
Once approved it is beaded out into one epic (`br create … -t epic --slug
ep-<plan>`), and its frontmatter names it (`epic: <id>`). From then on the
plan's progress is the epic's closed beads, which `tasks/INDEX.md` shows in
its Plans table. The plan's body is not edited to track progress; only its
frontmatter `progress` line mirrors the epic (`docs/plans/README.md`).

Beading out, in order:

1. **Two implementation specs.** A fresh Claude subagent and Codex (Sol,
   high effort, through `codex-orchestrator`) each write one against the
   plan, independently, with the Ghidra notes and the code as ground truth
   and every rule cited.
2. **Merge.** The lead merges them, keeping what each does better.
   A disagreement the trace or the original can settle becomes a `question`
   bead, not a vote. One refinement round in a fresh session follows.
3. **Bead out.** The lead creates the epic and its dotted beads with `br`
   only, in the template above, with `blocks` edges and the kind labels.
4. **Polish.** Three rounds, then one dedup round. Each round is a fresh
   subagent that rereads AGENTS.md, this page and the epic's beads, and
   returns proposed `br update`/`br dep`/`br create` commands with a reason
   for each: missing context, a criterion that cannot be checked, a wrong or
   missing edge, an uncited behaviour, a duplicate. It never removes a
   citation or a test. The lead applies what holds up, then runs `br lint`,
   `br dep cycles` and `scripts/task-index.py`. Stop when a round proposes
   nothing of substance.
5. **Tom reads** the epic on `tasks/INDEX.md` before work starts.

## The chain

```text
question ──▶ review ──▶ port ──▶ acceptance (region, cells)
                         ▲            ▲
          diagnose ──────┘   fixture ─┘
```

A `blocks` dependency points from the waiting node to the one it waits on
(`br dep add <waiting> <first>`). An acceptance node lists its cells from the
C6 report it was built from. Close it only with a C6 run that shows the
region passing: name the run in the close reason. Never mask a region to
close a node; a mask needs proof of nondeterminism and a written
justification (plan doc, C6).

## Who writes it

One writer for the graph's shape: the lead session creates, re-scopes and
closes nodes. An agent picks work with `bv --robot-triage`, claims it
(`br update <id> --claim`), logs progress as comments, ticks criteria as they
pass, names its node ID in every report, and proposes the nodes its work
uncovered (`discovered-from`); the lead adds them after review. A decompile
often raises the next question, so the graph is expected to grow.

A node closes only with every box checked and a close reason that names the
evidence: the test, the gate run, the save, day and values. The commit that
lands the work lists the bead IDs it closes.

The repository is public. A node names agents by role or name, never by a
private platform identifier, and carries no original game data.

## Commands

```bash
export RUST_LOG=error                      # quiet br's dependency logs
br ready --json                            # unblocked, open, not deferred
bv --robot-triage                          # ranked picks with reasons (PageRank, what each unblocks)
bv --robot-next                            # the single top pick
br show <id> --json                        # one node with its dependencies
br update <id> --claim --actor lead        # take it (status in_progress)
br update <id> --assignee <agent> -s in_progress
br comments add <id> "…"                   # progress log
br update <id> --check-acceptance 1        # tick a criterion (number or text)
br close <id> --reason "C6 run <id>: region passes in all 11 cells" --actor lead
br create "Q: …" -t task -p 1 -l question,ghidra,worker-ok --slug q-<name> --description-file note.md --acceptance-criteria "- [ ] …"
br create "…" -t task -p 2 -l port --parent <epic> --description-file bead.md --acceptance-criteria "- [ ] …"
br lint                                    # missing criteria and template sections
br dep cycles
br dep add <waiting-id> <first-id>         # blocks
br dep add <child-id> <epic-id> -t parent-child
br defer <id>                              # parked by decision
br sync --flush-only                       # write .beads/issues.jsonl
```

Never run bare `bv` from an agent: it opens the interactive viewer. Use its
`--robot-*` flags.

## Relation to the other records

- The graph holds the work and its order.
- Evidence stays where it was: the plan doc
  (`docs/plans/2026-09-22-tooling-tactical-106-cell-acceptance.md`), the
  Ghidra notes, the C6 reports.
- `HANDOFF.md` and `progress.json` say where a session stopped.
- The strategic audit features keep their own ledger
  (`docs/qa/2026-09-08-full-functionality-audit/`). The graph covers the
  tactical acceptance, the ground assault, the Ghidra gaps, the REBEXE map
  and the mod surface.
